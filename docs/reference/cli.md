# CLI reference

Every `vibey` command and subcommand, generated by reading
[`src/vibey/cli/main.py`](../../src/vibey/cli/main.py) directly. `vibey
<command> --help` is always authoritative if this page and the code
disagree.

## Global options

These apply to every command; they must come before the subcommand name.

| Option | Default | What it does |
|---|---|---|
| `--version` | — | Print the version and exit. |
| `--verbose` / `-v` (repeatable) | `0` | `-v` debug, `-vv` also third-party libraries, `-vvv` full payloads. |
| `--quiet` / `-q` | off | Warnings and errors only. |
| `--log-level` | unset | `DEBUG`, `INFO`, `WARNING`, `ERROR`, or `CRITICAL`. Overrides `-v`. |
| `--log-file PATH` | unset | Also write redacted JSON lines to this file. |

## `vibey new NAME`

Create a project and enqueue its first DESIGN interview.

| Option | Default | What it does |
|---|---|---|
| `--repo PATH` | `.` | Repository the project builds against. |
| `--max-cycles N` | `10` | Cap on delivery cycles before the project stops. |
| `--max-cycle-dollars F` | unset | Per-cycle dollar cap; tripping it parks a `budget_exhausted` gate instead of starting more sessions. |
| `--max-cycle-turns N` | unset | Per-cycle engine-turn cap. |
| `--skills-context-mode {off,shadow,inject}` | `off` | `vibey-skills` retrieval mode — see [Configuration reference](configuration.md#skills_context). |
| `--skills-context-budget N` | `6000` | Token budget for skills retrieval (1,000–32,000). |

## `vibey answer GATE_ID`

Answer a parked human gate. Exactly one of the following modes is required
(or `--defaults` alone for interview gates):

| Form | Used for |
|---|---|
| `QUESTION_ID=ANSWER [QUESTION_ID=ANSWER ...]` | Interview gates, answered per question. Combine with `--defaults` to fill in every other question's default. |
| `--defaults` | Interview gates: accept every question's default. Question keys are model-minted per run, so this needs none. |
| `--choice VALUE` | Deployment and triage gates: sends `{"choice": VALUE}`. |
| `--verdict VALUE` | Review gates: sends `{"verdict": VALUE}` — `accept`, `changes`, `cancel`, `approve`, or `request_changes`. |
| `--raw JSON` | Any other gate shape, e.g. raising a budget cap: `--raw '{"max_dollars": 25}'`. |

## `vibey work PROJECT_ID`

Process one ready DESIGN job. Live engine use is explicit and capped.

| Option | Default | What it does |
|---|---|---|
| `--provider {scripted,claudeloop}` | `scripted` | `scripted` needs no live engine; `claudeloop` runs a real session. |
| `--max-turns N` | `1` | Turn cap for this one job. |
| `--max-dollars F` | `0.25` | Dollar cap for this one job (max `10`). |

## `vibey design`

Bare `vibey design` prints help. Subcommands:

| Subcommand | What it does |
|---|---|
| `design resume PROJECT_ID` | Enqueue or resume the project's DESIGN interview. |
| `design accept PROJECT_ID [--spec-json PATH] [--visual/--no-visual]` | Accept the synthesized spec (optionally importing JSON first) and choose whether to enter the VISUAL_DESIGN interstitial. Defaults to `--no-visual`; the choice is never implicit. |

## `vibey visual`

Bare `vibey visual` prints help. Subcommands:

| Subcommand | What it does |
|---|---|
| `visual accept PROJECT_ID` | Accept the reviewed visual plan and enter BUILD. |
| `visual waive PROJECT_ID` | Explicitly waive the visual plan (the inventory must still be complete) and enter BUILD. |

## `vibey watch [PROJECT_ID]`

Live TUI dashboard: current phase, queue, engine circuits, active worktrees,
and a ledger tail. Defaults to the most recently created project.

| Option | Default | What it does |
|---|---|---|
| `--replay` | off | Replay historical ledger events instead of following live state. |
| `--speed F` | `1.0` | Replay playback speed multiplier. |

## `vibey recover`

Recover stuck leased jobs (e.g. after a worker crash), setting them back to
`ready`.

| Option | Default | What it does |
|---|---|---|
| `--project ID` | unset | Recover jobs for one project. |
| `--all` | off | Recover jobs for every project. |

One of `--project` or `--all` is required.

## `vibey status [PROJECT_ID]`

Show the project's phase, cycle, queue depth, and engine circuits. Defaults
to the most recently created project.

| Option | Default | What it does |
|---|---|---|
| `--json` | off | Emit machine-readable JSON instead of text. |

## `vibey engines [PROJECT_ID]`

Show recorded engine health, circuit-breaker state, and selection metrics
for a project.

## `vibey cost [PROJECT_ID]`

Show spend per engine against the cycle and total budget caps for a project.

## `vibey ledger`

Bare `vibey ledger` prints help. Subcommand:

| Subcommand | Option | Default | What it does |
|---|---|---|---|
| `ledger show [PROJECT_ID]` | `--limit N` / `-n` | `50` | Show the most recent N events. |
| | `--phase PHASE` | unset | Filter to one phase, by name or value. |
| | `--kind KIND` | unset | Filter to one event kind, by name or value. |

## `vibey deploy`

Manage and inspect Phases ④–⑥. Bare `vibey deploy` prints help. Subcommands
(each takes an optional `PROJECT_ID`, defaulting to the latest project):

| Subcommand | What it does |
|---|---|
| `deploy status` | Active deployment phase, live endpoint, verification state. |
| `deploy inspect` | The active `DeploymentSpec`, its scope digest, and monthly budget. |
| `deploy plan` | Evaluate the pending IaC changeset for destructive operations and budget adherence. |
| `deploy cancel` | Halt an in-flight deployment and clean up ephemeral cloud resources. |
| `deploy rollback` | Trigger an immediate, policy-bound rollback to the previous stable revision. |

## `vibey doctor`

Check engine health and auth status; optionally run the conformance suite
or an in-cluster preflight.

| Option | Default | What it does |
|---|---|---|
| `--conformance` | off | Run the 9-check conformance suite against each installed engine. |
| `--engine ENGINE` | unset (all installed) | Check one engine only. |
| `--record` | off | Persist preflight (and conformance, with `--conformance`) results to `engine_health`. |
| `--project ID` | latest | Project to record health for, with `--record`. |
| `--cluster` | off | Run the in-cluster preflight instead (DSN, workspace, secrets, database, migrations) — see [Kubernetes guide](guides/kubernetes.md). |

## `vibey operator`

Run the Kubernetes operator, reconciling `VibeyProject` custom resources.
Requires the optional extra: `pip install 'vibey[operator]'`.

| Option | Default | What it does |
|---|---|---|
| `--namespace NS` | unset (cluster-wide) | Watch a single namespace instead of the whole cluster. |

## `vibey worker`

Long-running worker: listens for `vibey_job_ready`, dispatches jobs across
every phase.

| Option | Default | What it does |
|---|---|---|
| `--engines LIST` | all configured | Comma-separated allowlist of engines to use for engine-driven jobs. |
| `--parallelism N` / `-j N` | `1` | Concurrent job loops (1–16). |
| `--once` | off | Process one job and exit, instead of running forever. |
| `--provider {scripted,claudeloop}` | `scripted` | Design/decompose provider. |
| `--max-turns N` | `25` | Turn cap per engine session. |
| `--max-dollars F` | `2.0` | Dollar cap per engine session (max `10`). |
| `--project ID` | latest | Project to work on. |
| `--wait-for-project SECONDS` | unset | Poll for a project instead of exiting when none exists yet — for long-lived deployments, where exiting means a restart loop. |
| `--azure {memory,az}` | `memory` | `memory` is a safe, no-op default; `az` uses the real Azure CLI (`az login` required) and mutates real resources on consented deploys. |
